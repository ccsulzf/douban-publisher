# 自动启动调试 Chrome 设计

## 目标

让 `npm run fill` 在本地 CDP 端口尚未启动时，自动启动专用的 Chrome 实例并继续预填流程。

## 方案选择

1. 保持手动启动：零代码变化，但每次首次运行都需要复制命令。
2. 总是重新启动 Chrome：会打断用户已打开、可复用的调试实例。
3. 先连接，失败时再启动（采用）：兼容现有手动流程，只在 `127.0.0.1:<port>` 被拒绝连接时启动 Chrome。

## 行为

- 默认使用 `9222`，并继续支持 `DOUBAN_CDP_PORT`。
- 首次连接被拒绝时，通过 macOS 的 `open -na "Google Chrome" --args` 启动独立 Chrome，传入远程调试端口和 `$HOME/.douban-cdp-profile`。
- 启动后轮询 CDP 的 `/json/version`，就绪后再次由 Playwright 连接。
- Chrome 启动失败或在限时内未就绪时，抛出包含端口和人工启动命令的明确错误。
- 已连接的浏览器不会被脚本关闭；脚本不尝试登录或发布。

## 测试

- 为启动参数、连接拒绝后的启动与重连、非连接错误直接抛出、CDP 就绪等待编写 Node 内置测试。
- 不在测试中实际启动 Chrome。
