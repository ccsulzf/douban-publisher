# 做了一个租房看房记录小程序，想请 V 友帮忙体验和拍砖

大家好，我是这个小程序的开发者。

最近我一直在做一个租房记录与现场看房小程序。它不是房源发布或聚合平台，也不帮用户判断某套房“一定值得租”，主要想解决的是：已经拿到几套候选房源后，怎么把零散信息记清楚，最后更有依据地做选择。

## 为什么做这个小程序

我在整理租房决策这件事时，发现信息通常散落在很多地方：

- 房源条件和费用在中介或房东的聊天记录里；
- 房间问题在相册和临时备忘录里；
- 通勤时间需要反复打开地图查询；
- 周边配套当时搜过，过几天就不记得对应哪套房；
- 连续看过几套以后，很容易把采光、噪音、楼道和付款方式记混。

所以我想做一个更聚焦“看房现场”和“房源取舍”的工具。核心流程很简单：录入候选房源，现场检查房屋和公区，查看周边与通勤，最后把两套候选房放在一起比较。

![小程序主要功能：房源记录、现场检查、通勤、周边和房源对比](https://raw.githubusercontent.com/ccsulzf/douban-publisher/main/docs/assets/v2ex/overview.jpg)

## 目前做了什么

### 1. 记录房源和费用信息

每套房可以记录面积、楼层、电梯、月租、押金、付款方式、租期和租住渠道等信息。我的想法不是让大家填一张很长的表，而是把后面真正会参与比较的条件留在同一个地方。

### 2. 把现场看房拆成可以复查的项目

看房时可以分别记录房屋内部和公共空间的情况，例如空间、采光、通风、噪音、气味、楼道、电梯、入口路线、雨天和夜间通行。每个检查项都可以补备注，避免回家以后只剩下一句“当时感觉还行”。

![房屋检查：记录空间、采光、通风、噪音和气味](https://raw.githubusercontent.com/ccsulzf/douban-publisher/main/docs/assets/v2ex/room-inspection.jpg)

### 3. 按自己的目的地看通勤

可以保存公司或其他常去地点，再查看候选房源到目的地的公交、驾车和骑行方案。除了总时间，也能继续看步行接驳、线路、站点、距离等信息。

我希望这里表达的不是“离公司几公里”，而是每天实际怎么走、要不要换乘，以及这种通勤自己能不能长期接受。

![公交通勤详情：步行接驳、线路、站点和预计用时](https://raw.githubusercontent.com/ccsulzf/douban-publisher/main/docs/assets/v2ex/transit-detail.jpg)

### 4. 查看房源附近的生活配套

目前可以按类型查看房源附近的常用配套。做这个功能的原因也比较朴素：当时在地图里搜到的超市、菜市场、餐饮、医院或公园，过几天经常记不清对应的是哪套房。

### 5. 把两套候选房放在一起比较

对比页会把两套房的费用、房屋检查、公区检查、周边和通勤并排展示。这里不替用户给房子打一个“综合分”，因为每个人的优先级差别很大；我更希望它把差异摊开，让人看清自己愿意为哪一点多花钱，又不能接受哪些问题。

![房源通勤对比：并排查看不同方式的时间和距离](https://raw.githubusercontent.com/ccsulzf/douban-publisher/main/docs/assets/v2ex/commute-comparison.jpg)

## 我希望它解决的是“怎么选”，而不只是“怎么记”

市面上已经有很多记事、表格和地图工具，单独记录某一类信息并不难。这个小程序更想做的是把一次租房决策的上下文串起来：

`候选房源 → 现场检查 → 周边与通勤 → 房源对比 → 最终取舍`

我目前比较克制地控制功能范围，不准备在里面做房源交易，也不想替用户生成一个看似精确的结论。工具负责把事实和自己的判断留住，签约前仍然需要用户核实房源、合同和各项费用。

## 技术实现

项目目前基于 **uni-app + Vue 3 + TypeScript** 开发，状态管理使用 **Pinia**，云端使用 **uniCloud**，周边和通勤能力接入了**腾讯地图**相关服务。

这篇主要是介绍产品，就不展开具体实现了。如果大家对某一块技术细节感兴趣，我可以后面再单独整理，例如：

- 小程序里的多模块现场记录如何组织；
- 公交、驾车、骑行路线数据如何缓存；
- 两套房源的不同模块如何按需加载和对比；
- uni-app 项目在微信小程序端的一些开发取舍。

## 目前的状态

小程序目前可以体验，但仍在持续迭代。我自己做久了以后，已经很难判断一些交互和字段对第一次使用的人是否足够直观，所以这次更想听听没有参与开发的人怎么评价。

现阶段我也没有拿运营数据来证明它“已经有用”。如果大家实际打开后觉得流程太重、不愿意在看房现场使用，或者看不懂某个功能，这些反馈对我反而更重要。

## 想请大家重点帮我看看

如果你愿意体验，我特别想知道下面几个问题：

1. 第一次打开时，能不能快速理解这个小程序是做什么的？
2. 现场检查的项目是有帮助，还是会让人觉得填写负担太重？
3. 周边、通勤和房源对比里，哪一项最有价值，哪一项最鸡肋？
4. 如果你正在租房，还有什么信息是签约前很想比较、但现在没有覆盖的？

直接在回复里拍砖就行。界面、流程、文案、功能优先级或技术实现上的意见都欢迎，我会认真看。
